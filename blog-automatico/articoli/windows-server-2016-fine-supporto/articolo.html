In tanti studi e piccole aziende c'è un server in uno sgabuzzino che "va da anni e nessuno lo tocca": tiene le cartelle condivise, il gestionale, magari la posta o gli utenti di rete. Molto spesso su quella macchina gira Windows Server 2016. Il 23 ottobre Microsoft ha ricordato la data: Windows Server 2016 fine supporto il 12 gennaio 2027, con l'ultimo aggiornamento di sicurezza in quella stessa giornata. Mancano meno di tre mesi, e a cavallo ci sono le feste. In questo articolo ti spiego cosa cambia davvero, come capire se il tuo server è coinvolto e quali strade hai, dalla più economica alla più comoda, per arrivare a gennaio senza sorprese.

Windows Server 2016 fine supporto: cosa succede il 12 gennaio 2027

Come riportato da BleepingComputer, che cita il Message Center di Microsoft, l'aggiornamento di sicurezza di gennaio 2027 sarà l'ultimo disponibile per questa versione. Dopo quella data il server continua ad accendersi e a funzionare, ma:

  • non riceve più le patch mensili, cioè le correzioni alle falle di sicurezza scoperte da lì in avanti;
  • la scadenza vale per tutte le edizioni: Standard, Datacenter, Essentials e MultiPoint Premium;
  • nello stesso giorno termina anche il supporto alle funzioni tipiche di Windows Server 2016 Essentials, compreso l'Accesso Web remoto (Remote Web Access) che molti piccoli uffici usano per raggiungere i file da casa.

Il "supporto esteso" è già l'ultima fase: quello principale, con le novità e le correzioni non di sicurezza, era finito a gennaio 2022. Dal 13 gennaio, quindi, ogni nuova vulnerabilità resterà aperta per sempre.

Perché un server senza aggiornamenti è un rischio serio

Vedo spesso pensare: "Tanto il server non naviga su Internet". Purtroppo non basta. Il server è il punto in cui finiscono tutti i dati dello studio e a cui sono collegati tutti i PC. Se un ransomware entra da una email aperta su un computer qualsiasi, la prima cosa che cerca è proprio il server, per cifrare le cartelle condivise e, se può, i backup.

Un sistema senza patch è la porta più facile: gli attaccanti usano falle note da tempo proprio perché sanno che molte macchine non vengono aggiornate. In più c'è un aspetto normativo: il GDPR chiede misure di sicurezza adeguate, e un sistema fuori supporto che custodisce dati di clienti è difficile da giustificare dopo un incidente. Per chi rientra nella NIS2 il tema è ancora più diretto, ne ho parlato nell'articolo sulla scadenza NIS2 del 31 ottobre.

Come capire se il tuo server è coinvolto

Bastano due minuti, anche senza essere tecnici:

  1. accedi al server (o chiedi a chi lo gestisce) e premi Windows + R, scrivi winver e premi Invio;
  2. se la finestra riporta "Windows Server 2016" o la versione 1607, il server è tra quelli che perdono il supporto;
  3. controlla anche le macchine virtuali: spesso un server "nuovo" ospita al suo interno un vecchio Windows Server 2016 con il gestionale.

Già che ci sei, fai un elenco di cosa gira su quel server: condivisione file, gestionale, database, stampanti, accesso remoto, antivirus centralizzato. Ti servirà per scegliere la strada giusta.

Occhio a SQL Server 2016

Molti gestionali usano un database SQL Server installato sullo stesso server. La versione 2016 è già uscita dal supporto il 14 luglio 2026. Se è il tuo caso, conviene pianificare i due aggiornamenti insieme, coinvolgendo il fornitore del gestionale per sapere quali versioni supporta.

Le strade possibili prima di gennaio

Non esiste una risposta valida per tutti. Queste sono le opzioni che propongo di solito, in ordine di frequenza.

1. Passare a Windows Server 2025

È la strada che Microsoft consiglia. Windows Server 2025 è disponibile da novembre 2024 e, secondo la pagina del ciclo di vita, riceverà aggiornamenti di sicurezza fino al 14 novembre 2034. Microsoft offre una versione di prova gratuita di 180 giorni, utile per verificare prima che il gestionale funzioni. Se l'hardware ha otto o nove anni, quasi sempre conviene comprare un server nuovo e migrare lì i servizi, invece di aggiornare la vecchia macchina: il disco e l'alimentatore di un server così datato sono un rischio a parte.

2. Valutare se il server serve ancora

A volte il server fa poco: qualche cartella condivisa e gli utenti di rete. In questi casi può avere senso spostare i file su SharePoint e OneDrive di Microsoft 365 o su un NAS ben configurato, ed eliminare il server. Attenzione però: anche nel cloud servono un backup separato e regole di accesso chiare. Ne parlo negli articoli sul backup di Microsoft 365 e sulla sicurezza del NAS.

3. Comprare tempo con gli aggiornamenti estesi (ESU)

Microsoft offre gli Extended Security Updates, aggiornamenti di sicurezza a pagamento per un massimo di tre anni. Secondo la documentazione ufficiale, per i server in ufficio si attivano tramite Azure Arc (un servizio che collega il server al cloud Microsoft), solo per le edizioni Standard e Datacenter e in genere con licenze a volume coperte da Software Assurance. La fatturazione parte dal 13 gennaio 2027. Per molti piccoli uffici, con una licenza OEM comprata insieme al server, questa strada non è percorribile o non conviene: va verificata caso per caso con il rivenditore. Ricorda che gli ESU coprono solo le falle critiche e importanti: sono un ponte, non una soluzione.

4. Lasciare tutto com'è

Lo cito perché è la scelta che vedo più spesso, di solito per inerzia. Se proprio il passaggio slitta di qualche settimana, almeno isola il server: nessun accesso diretto da Internet, accesso remoto solo tramite VPN con doppia autenticazione, backup giornaliero su un supporto scollegato e verifica che il ripristino funzioni.

Un calendario realistico per arrivare pronti

Con le feste di mezzo, i tempi si accorciano. Ecco come organizzerei le prossime settimane:

  • entro metà novembre: inventario di cosa fa il server, contatto con il fornitore del gestionale, scelta della strada;
  • entro fine novembre: ordine dell'hardware o delle licenze (i tempi di consegna a fine anno possono allungarsi);
  • dicembre: installazione e migrazione in un fine settimana o nei giorni di chiusura, con un backup completo prima di iniziare;
  • prima del 12 gennaio: prova dei servizi, delle stampanti e dell'accesso remoto, poi spegnimento del vecchio server, senza buttarlo finché non sei sicuro che i dati siano tutti al loro posto.

Se vuoi un aiuto per l'inventario o per la migrazione, trovi come lavoro nella pagina Come lavoro e i servizi di assistenza in Servizi.

Domande frequenti

Dopo il 12 gennaio 2027 il server smette di funzionare?

No. Windows Server 2016 continua ad avviarsi e a fare il suo lavoro, ma non riceve più correzioni di sicurezza. Il rischio cresce ogni mese che passa.

Posso aggiornare direttamente da 2016 a 2025?

Microsoft prevede l'aggiornamento "sul posto" da versioni precedenti, ma su server con molti anni di servizio preferisco quasi sempre un'installazione pulita su hardware nuovo, con migrazione dei dati: è più sicura e lascia il vecchio server come rete di salvataggio.

Ho Windows Server 2019: devo preoccuparmi?

Non subito: Windows Server 2019 è supportato fino a gennaio 2029. Conviene però metterlo già in programma, così da non trovarsi di nuovo con l'acqua alla gola.

Gli ESU convengono a un piccolo studio?

Raramente. Richiedono licenze e configurazioni specifiche e coprono solo le falle più gravi. Hanno senso quando un software indispensabile non funziona ancora sulle versioni nuove e serve tempo per sostituirlo.
